## Key Decisions

1. **Deterministic UUIDs (uuid5)** — All `caseId` and `evidenceId` values use `uuid.uuid5(namespace, logical_name)`. Regenerating produces identical IDs every run. Bookmarked demo URLs & cached responses remain stable.

2. **Stdlib only (no Faker)** — Zero-dependency usage: `python generate_cases.py` works with any Python 3.9+ interpreter. Data is hand-curated in the script. `jsonschema` optional for full validation.

3. **Citation integrity enforced** — `rebuttalDraft.citations[*].evidenceId` must reference real evidence in the same case. Validator (`_manual_validate`, `_schema_validate`) explicitly checks this.

4. **Case 05 has no rebuttalDraft** — Intentional: the case is in `evidence_gathering` status (AI drafting hasn't run yet). API & SPA must handle absent rebuttalDraft gracefully. This is a correct schema-allowed state.

5. **Live daysRemaining** — `deadline.daysRemaining` is recomputed from `date.today()` on every generator run. Hardcoded `dueDate` is stable; the derived integer is always fresh. Demo deadline urgency is realistic if data is regenerated before demo day.
