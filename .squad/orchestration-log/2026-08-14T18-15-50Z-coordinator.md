## Known Outstanding Risk

**51 refs/pull/*/head refs on origin still pin the complete pre-squash history.**

These branch refs (in the GitHub pull request namespace) remain publicly fetchable and contain the full unsquashed history prior to the squash. Implications:

- A user with direct access to GitHub API can fetch `refs/pull/*/head` to see the pre-squash commits
- This is orthogonal to the main-branch squash
- User (Jorge) reviewed three options:
  1. **New repository** — clean slate but disruptive to existing clones/workflows
  2. **Delete and recreate** — same disruption
  3. **GitHub Support escalation** — request PR refs cleanup (slow, uncertain)
  4. **Accept as-is** — publish with awareness that PR history is unsquashed (chosen by user)

**User's decision:** Accept and publish as-is. The sensitive values are not reintroduced in the PRs themselves; only the **pre-redaction history** is visible via those refs. This is considered acceptable risk given the overhead of the other options.

**Actual mitigation path:** Service Principal credential rotation is the operational mitigation. This removes the utility of any exposed credentials, even if accessed via PR refs. This action is pending and must be completed by the organization's identity/security team.
